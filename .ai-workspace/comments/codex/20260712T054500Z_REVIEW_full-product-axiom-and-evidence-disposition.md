## Executive Finding

The four reported storage and transport blockers are repaired. The broader
product review nevertheless rejects the earlier full-build interpretation.

The current implementation has two real but separate systems:

1. a local deterministic WM kernel creates semantic objects, checks them,
   applies attributed acceptance, and projects accepted/published state;
2. rc.3 GraphFunctions traverse declared graphs and admit preconstructed exact
   refs through a reference-and-digest bridge.

The selected GraphFunctions do not execute the WM kernel. The F_P turn does not
author the semantic proposal. Accepted and published WM states are local digest
projections over replay-derived witnesses, not native ABG replay projections.
Those are migration gaps, not implementation details and not conditions that a
green test count can waive.

## Confirmed Findings

### P0 — Native constructive carrier is not realized

`GraphFunction` declarations contain graphs, vectors, nodes, environments, and
typed contracts, and ABG traverses them. Their current bindings do not execute
the WM semantic kernel. The reference harness orders semantic construction,
checking, acceptance, persistence, and publication around those runs.

This fails as-built checks D2, S2, S3, M1, M2, M4, and X2. The exact diagram
backfill and failure table are in
`build_tenants/typescript/design/95-rc3-reference-bridge-as-built-review.md`.

### P0 — F_P authorship was previously overstated

The semantic proposal exists before the F_P turn. The rc.3 adapter returns its
already-bound evidence ref so ABG can exercise admission and closure. That is
valid reference transport but not calibrated probabilistic authorship.

REQ-ODD-WORLD-MODEL-BUILD-VERIFY-009 and ODD-CARRIER-002/005 remain open.

### P0 — Candidate Markov verification was self-asserted

The fixture previously wrote `held_out_treatment_verification.result=passed`
without running a treatment test. Candidate Markov-object v1 now permits only
`inconclusive`; both TypeScript and JSON Schema reject a locally asserted
`passed`. A future passed result requires a separately admitted verification
contract.

The attribute ledger, assurance record, distributed evidence resolution, and
held-out treatment proof remain open. The first slice is semantic plumbing, not
the full source-to-ledger-to-object proof.

### P1 — Semantic state is not replay-native

`AbgAdmissionWitness` is a WM projection over canonical ABG events. The events
and exact subject refs are recoverable. `AcceptedSemanticCut` and
`PublishedSemanticCut` are then constructed by the local WM kernel from those
witnesses. They must not be described as ABG aggregates or native replay state.

The target design remains valid as a migration contract. The as-built design
fails D4 and M1 until a successor payload/projection contract closes this gap.

### P1 — The pinned GLC line is only a proving overlay

odd_glc `0.1.0` supplies exact startup binding, lifecycle overlay, policy refs,
and registry interpretation. It does not expose the successor downstream
program carrier required by the floating Product boundary. ODD-CARRIER-012
remains open.

### P1 — Product completeness remains materially open

The current slice has no accepted attribute ledger or independent assurance
surface; no common-model adoption witness; no published node/link
supersession witness; no covariance/adjoint chain; no executable mapping; no
installed builder-product proof; and no immutable release cut.

These are named requirement dispositions, not unspecified future work.

The closed context-fidelity vocabulary also has no value for unknown or
unmeasured fidelity. The current slice proves known loss, exclusion,
truncation, and gap disclosure, but CONTEXT-MEMORY-CONSTRAINT-004 remains open
until that contract decision is made.

## Repaired Reported Defects

- Python hashes the raw received request shape before defaults or null removal.
- Append-local snapshot identity cannot retarget under an interleaved commit.
- Typed operation failures survive Python exit code `2` through the TypeScript adapter.
- Store construction/configuration failures emit one typed JSON result rather than a traceback.
- Storage no longer seals provider-authored `verification: verified` into an attestation.
- Optional protocol fields have a cross-language omission test.
- Attestation and effect observation remain separate; failed readback cannot emit successful publication.
- Context basis carries exact source-observation and physical-snapshot refs and recomputes its dependency digest.
- Model-facing context dependencies and disclosures must match the supplied exact basis even after all local digests are recomputed.
- Context schemas reject exact-payload claims, undeclared truncation, and inconsistent loss/fidelity combinations.
- Query rejects any attested physical snapshot absent from its exact context basis.
- Every downstream digest-bearing semantic carrier is recomputed before consumption.
- Semantic-link digests, closed role vocabulary, closure rules, and supersession direction fail closed.
- Bounded mesh cuts are recomputed against the supplied publication/link catalogs, so a digest-valid cut cannot omit reachable dependencies.
- Composition resolves only exact `PublishedSemanticCut` components and uses one shared schema.
- FpML now uses namespace-aware XML parsing and bounded syntax validation rather than regular-expression traversal.

storage evidence, and its migration boundary is now explicit. It is not the
native product fixed point.
