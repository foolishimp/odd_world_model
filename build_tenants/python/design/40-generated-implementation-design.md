## 6. Implementation Rules

### 6.1 Python First

The first live line stays entirely under the Python tenant.

That means:

- GTL carrier implementation is Python
- deterministic materialization is Python
- query/proof/install surfaces are Python

Future serving or DB-backed query planes may be added later, but they remain
downstream projections rather than replacements for the current carrier.

### 6.2 No Compatibility Layers

The deleted `sandbox/*` compatibility path stays deleted.

Canonical retained implementation lives under:

- `build_line/`
- `world_model/`
- `query/`
- `proof/`
- `release/`

No new wrapper layer should be introduced just to preserve old names.

### 6.3 No Manual Install Mirroring

Installed `.genesis/` or `.genesis/odd_world_model/` trees are refreshed by running install,
not by hand-copying source standards or runtime files into installs.

### 6.4 Traceability And Requirement Discipline

Every implementation module added downstream of this surface should preserve:

- requirement traceability to `REQ-ODD-WORLD-MODEL-*`
- scenario traceability to the generated scenario surface
- explicit boundary between source evidence, semantic substrate, and
  projections
