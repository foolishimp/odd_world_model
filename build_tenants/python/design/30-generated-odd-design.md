## Design Principle

`odd_domain` is designed as a Python ODD product whose constructive carrier is
an explicit GTL/ABG runtime and whose semantic substrate is a ledger-backed
world-model line.

The design keeps three boundaries explicit:

1. released `odd_sdlc` governs the mutable `odd_domain` source project as a software product line
2. `odd_domain` itself governs world-model construction and composition
3. query and proof remain downstream projections over the governed semantic build line

The core semantic chain in this design is:

`source -> tracing -> assurance -> attribute ledger -> immutable object cut -> published domain artifact -> composed world model -> query/proof projection`

This design avoids two failure modes:

- no bespoke loader sprawl where meaning hides inside one-off scripts
- no query-first architecture where the serving layer becomes the constitutional source of truth

### Design Decisions

- Typed asset families are the runtime-visible contract for the domain; they prevent semantic drift between build-line stages.
- Graph functions remain the constructive carrier; deterministic `F_D` materializers do the bounded record-writing work underneath.
- Executive programs are kept narrow and replayable so the carrier can converge one lawful edge at a time.

### Interfaces

- `catalog()` exposes the current graph-function and asset inventory
- `start()/iterate()` drive edge selection and FP dispatch
- `workspace_assets` binds abstract assets to concrete paths under `specification/` and `build_tenants/python/`

## C-WORLD: Ledger-Backed Semantic Substrate

**Realizes**: REQ-ODD-DOMAIN-BUILD-CONSTRAINT-001, REQ-ODD-DOMAIN-BUILD-CONSTRAINT-002, REQ-ODD-DOMAIN-BUILD-CONSTRAINT-003, REQ-ODD-DOMAIN-WORLD-OBJECT-001 through REQ-ODD-DOMAIN-WORLD-OBJECT-012

### Design Decisions

- The attribute ledger is the immediate semantic source for accepted claims.
- A Markov object is an immutable object cut projected from that ledger, not a mutable row-model record.
- Temporal reference artifacts remain first-class semantic companions to object interpretation.
- Validation stays local to the world-model carrier so published artifacts can be checked deterministically.

### Core Invariant

No published object attribute should exist unless it can be recovered through:

`object cut <- attribute ledger <- assurance <- tracing <- source`
